# Chris's requests of 2026-11-23: plan

Written at the usage edge (weekly 74%, rule 70%): nothing here is built yet. Each item: failing test first, gates,
test app rebuilt, CI checked. Order as below (data safety and rules first, then the shop, then the tidy-up).

## 1. Point buy: a warning for unspent points

- Rules check, a notice (not an error): "Point buy: N of 27 points unspent." when the method is point buy and points
  are left. Uses the table's own rules where set (`normalizeRules`, `spent` in src/aurora/pointBuy.ts).
- The board already shows "N of 27 points left" (BuildBoard.tsx, `.board-method-note`); it gets the warning colour
  while N > 0, so the two say the same thing.
- Test: pointBuy.test.ts (a character at 8/8/8/8/8/8 reports 27 unspent; one that spends all reports none; another
  budget is honoured).

## 2. The flagged characters: made rules legal, the player told what changed

One screen, "Make it legal", opened from the rules check when it has findings (and from the older-build notice).
It works on a copy first and shows before anything is saved:

- **Done for you** (one safe answer, the fix-it machinery of E3.1, src/aurora/findingFix.ts): a repeated pick taken
  out, a pick its choice no longer offers taken out, too many picks trimmed, leftover picks cleared.
- **Your call**, each with its options as buttons, nothing chosen for the player:
  - A 2024 species with a 2014 background and no increases (Talaan Istodaewl, Indigo Bones, Waldrom Brahms, Drago):
    "Use the 2024 rules for this background (three points, an origin feat)" or "Take a 2024 background" or "Leave it".
  - Cantrips off the class list (Carl Sneakers: Shape Water and Spare the Dying as Bard cantrips): "Replace with a
    Bard cantrip" (opens that choice) or "Keep as a table ruling" (marks the finding as accepted, see below).
  - More held than two hands hold (Xarthian): which items to put away, as a list to tick.
  - Point buy unspent (item 1): "Spend them" (opens the scores) or "Leave them".
- **Accepted as a table ruling**: a finding the player keeps on purpose is remembered on the character
  (`acceptedFindings: string[]`, rule plus detail) and shown apart, greyed, never counted as a fault again.
- **What changed**, as a list in plain words, with one button: "Add to this character's notes". It goes into a
  "Rules changes" entry of the Journal (src/ui/Journal.tsx; the journal already lives with the character and exports
  with it), dated. The import and move notes (`importReport`) can be added the same way, so all such notes have one
  home. Open question for Chris: Journal (proposed) or the Bag of Holding; the Journal needs no new place.
- The original is never overwritten silently: Apply writes the changes; Cancel leaves the character as it was.
- Tests: findingFix.test.ts for each automatic fix; a test per decision that each option leads to a character with
  that finding gone (or accepted); an end-to-end test of the screen on a seeded flagged character.

## 3. The shop: the one place items come from

- The Shop tab becomes the only way to add items, besides starting equipment. Removed: the "All items" list on the
  board's equipment panel and the adding part of EquipmentTab (BuildBoard.tsx two `<Browse type="Item">`, 
  EquipmentTab `part="adding"`); the custom-item form moves into the shop ("Something not on the shelves").
- A switch at the top: **Buy** (takes gold, the price shown, refused when the purse is short) or **Add** (free).
  Kept per character (`shopMode`), default Buy when the character has started play, Add while building.
- A shopkeeper: a name, a line of greeting that changes with the purse and the last purchase, at the head of the
  tab. No generated art (the standing rule): the keeper is words and the existing icon set; if Chris wants a
  drawn keeper, he supplies or approves the art.
- Categories first: a row of large tiles (Weapons, Armor and shields, Adventuring gear, Tools, Packs, Potions and
  poisons, Mounts and vehicles, Magic items, Trinkets, Everything). A tile opens the list with that category's
  filter set, and the filters stay the player's to change (the kept filters, item 4).
- The category of an item is one function used by the tiles, the list's badge and the bag (today `itemBadge` in
  Browse.tsx and the bag's own grouping): one source.
- Tests: shop.test.ts (buy takes gold, add does not, short purse refused, sell-back unchanged); an end-to-end
  test: no way to add an item outside the shop except starting equipment; a tile opens its filtered list.

## 4. Filters that survive a restart

- src/ui/keptFilters.ts writes through to localStorage (`charforge.filters.v1`, one JSON object, Sets as arrays),
  read once at start; a damaged value is ignored. "Clear filters" clears the stored value too.
- Test: unit (write, forget the in-memory map, read back from storage; damaged storage); end-to-end: set a filter,
  reload the page, the filter is there; clear it, reload, it is gone.
